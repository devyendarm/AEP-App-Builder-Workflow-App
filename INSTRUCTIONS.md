# AEP Workflow Automation — App Builder Setup Guide

Follow these instructions to set up, configure, and deploy the AEP Workflow Automation application on your company laptop.

---

## Technical Overview
This application is **100% native to Adobe App Builder and Adobe I/O**. It does not require any external servers or databases.

| Layer | Platform | Description |
|---|---|---|
| **Serverless Actions** | Adobe I/O Runtime | Handles file ingestion, orchestration, status polling, and retries. |
| **Key-Value State** | Adobe AIO State | Stores workflow definitions and live run histories. |
| **Event Triggers** | Adobe I/O Events | Triggers the orchestrator immediately when AEP completes data ingestion. |
| **UI Hosting** | Adobe CDN | Hosts the marketer React UI inside the Experience Cloud Shell. |
| **Authentication** | Adobe IMS | Handles user logins and controls Admin vs Marketer views. |
| **System Integration** | Adobe IMS OAuth | Automatically exchanges Developer Client ID/Secret for AEP API access. |

## Phase 0: Prerequisites (One-Time Laptop Setup)

### 0A — Install Node.js
* **Recommended:** **Node.js 20 (LTS)** for best compatibility with local development tools on Windows.
* **Corporate Laptop Alternative (Node.js 22):** If your corporate laptop restricts you to **Node.js 22**, you can still develop and deploy. However, note that the local development server (`aio app run`) has known compatibility bugs with Node 22 (like certificate generation crashes and watcher memory limits). In this case, you will bypass local testing and **deploy directly to the cloud** using `aio app deploy` (see Phase 6).
* Verify in your terminal:
  ```bash
  node --version
  npm --version
  ```

### 0B — Verify Adobe Access
1. Go to [https://developer.adobe.com/console/](https://developer.adobe.com/console/)
2. Confirm you can see your company's organization in the top-right dropdown.
3. Confirm you have permission to create projects.

---

## Phase 1: Install Adobe CLI and Authenticate

1. Install the global Adobe CLI:
   ```bash
   npm install -g @adobe/aio-cli
   ```
2. Log in using your corporate Adobe ID:
   ```bash
   aio login
   ```
   > A browser window will open. Log in and close the tab when successful.
3. Verify your organization alignment:
   ```bash
   aio where
   ```

---

## Phase 2: Configure Adobe Developer Console Projects

### 2A — Create the App Builder Project
1. Go to [https://developer.adobe.com/console/](https://developer.adobe.com/console/)
2. Click **"Create new project"** → **"Project from template"** → **"App Builder"**
3. Name it: `AEP Workflow Automation`
4. The console will automatically create `Production` and `Stage` workspaces.

### 2B — Add Required Platform APIs to the Stage Workspace
1. Click into the **Stage** workspace.
2. Click **"Add API"** → Add each of these (one at a time):
   - ✅ **I/O Management API** (enables CLI workspace management)
   - ✅ **Adobe Experience Platform** (enables Batch Ingest, Query Service, and Flow Service API access)
   - ✅ **I/O Events** (enables Event routing)
3. For each API, choose **"OAuth Server-to-Server"** as the credential type.
4. **IMPORTANT:** For the Adobe Experience Platform API, select a **Product Profile** that has developer access to AEP Sandboxes, Query Service templates, and Flow Service.
5. Click **"Save configured API"**.

---

## Phase 3: Initialize the Project on Your Laptop

1. Create a fresh directory on your laptop and navigate into it:
   ```bash
   mkdir aep-workflow-app
   cd aep-workflow-app
   ```
2. Run the initialization wizard:
   ```bash
   aio app init
   ```
3. Use the arrow keys and spacebar to select the following options:
   * **Organization:** Choose your company's Adobe Organization.
   * **Project:** Select `AEP Workflow Automation`.
   * **Workspace:** Select `Stage`.
   * **Features:** Select **both** `Actions: Serverless Actions` and `Web Assets: UI Frontend` (Press Space to check both).
   * **UI Framework:** Select `React Spectrum 3`.

---

## Phase 4: Copy the MVP Code into the Project

Overwrite the generic templates generated by `aio app init` with the custom code files from the `aep_workflow_mvp_FINAL.zip` archive:

### 4A — Overwrite Configuration
* Copy our `app.config.yaml` to the root `aep-workflow-app/app.config.yaml` (overwrite the default).
* Copy our `workflow.config.json` to `aep-workflow-app/workflow.config.json`.

### 4B — Overwrite Backend Actions
* Copy the following directories from the ZIP file into `aep-workflow-app/actions/` (overwriting the entire folders):
  - `actions/file-router/`
  - `actions/event-orchestrator/`
  - `actions/workflow-load/`
  - `actions/workflow-save/`
  - `actions/workflow-status/`
  - `actions/workflow-retry/`

### 4C — Overwrite Frontend
* Copy `src/App.js` from the ZIP file and paste it into `aep-workflow-app/web-src/src/components/App.js` (overwrite the generated file).
  > ⚠️ **Do NOT replace the whole web-src/ folder.** Just overwrite the `App.js` file inside `components/`. The other files generated in `web-src/` are required for compilation.

## Phase 5: Configure Credentials & Secrets

The backend actions use Adobe's built-in parameter manager. Secrets are encrypted in Adobe's secure runtime cloud.

### 5A — Configure Local Environment (For Local Development Only)
If you plan to run local tests, copy `.env.example` to `.env` in the root folder:
```bash
copy .env.example .env
```
Fill in your developer credentials:
```env
AEP_API_KEY=your_oauth_client_id
AEP_CLIENT_SECRET=your_oauth_client_secret
AWS_ACCESS_KEY_ID=optional_aws_key
AWS_SECRET_ACCESS_KEY=optional_aws_secret
AWS_REGION=us-east-1
LOG_LEVEL=info
```

### 5B — Configure Stage Workspace Secrets (Required for Deployments)
Add the secrets directly to the Adobe cloud workspace. This ensures they are encrypted and injected into actions at runtime.
1. Go to [developer.adobe.com/console](https://developer.adobe.com/console) → `AEP Workflow Automation` → **Stage** workspace.
2. Select **"Credentials"** → **"OAuth Server-to-Server"** to find your keys.
3. Click **"Workspace Secrets"** (or click into **Stage** → **Manage**).
4. Add the following secrets:
   * `AEP_API_KEY`: Enter your **Client ID**.
   * `AEP_CLIENT_SECRET`: Enter your **Client Secret**.
   * `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_REGION`: (Optional, only if S3 audit logging is enabled).

## Phase 6: Build and Deploy the Application

Run the installation and deployment command in your terminal:

```bash
# 1. Install root dependencies
npm install

# 2. Deploy to the cloud Stage workspace
aio app deploy
```
> 💡 **No need to run npm install in each action folder.** The `aio app deploy` command automatically resolves, installs, and builds dependencies for all 6 actions under the hood.

Upon successful completion, the CLI will output a secure Experience Cloud staging URL:
`https://experience.adobe.com/?devMode=true#/custom-apps/...`

---

## Phase 7: Register Webhook Event Subscription ⚠️ CRITICAL STEP

Once you deploy the app, you must link AEP events to your deployed action in the Developer Console:

1. Open [developer.adobe.com/console](https://developer.adobe.com/console) → `AEP Workflow Automation` → **Stage** workspace.
2. Click **"Add Event"** → Select **"Experience Platform"** → **"Platform notifications"** → Click **"Next"**.
3. Check the following event types:
   - `Experience Platform Source's Flow Run Succeeded`
   - `Experience Platform Source's Flow Run Failed`
4. Click **"Next"**.
5. For **"How to receive events"**, select **"Runtime Action"**.
6. In the Runtime Action dropdown, select: **`aep-workflow/event-orchestrator`**.
7. Name the registration: `AEP Ingestion Events`.
8. Click **"Save"**.

---

## Phase 8: Verify and Test the Application

1. Copy the deployment URL outputted by `aio app deploy` and open it in your browser.
2. Log in with your credentials.
3. Select a CSV file (under 50MB) and enter a campaign name.
4. Click **"Upload & Trigger Pipeline"**.
5. **Verify Steps:**
   - **INGEST** runs first. The file-router uploads the CSV batch to AEP.
   - Once AEP processes the ingestion, it fires an event. The `event-orchestrator` catches the event, automatically runs the **QUERY** template, and starts polling.
   - Once AEP Query Service finishes the query, the orchestrator triggers the **DESTINATION_FLOW** export step.

## Troubleshooting Guide

| Symptom | Cause | Resolution |
|---|---|---|
| **`CLIError: ux.wait is not a function`** during local run | Node 22 CLI compatibility bug with local dev server | Run **`aio app deploy`** instead to bypass local cert generation and host the app in the cloud. |
| **`@parcel/watcher` crashes** with memory limit errors | Node 22 native module issue on Windows | Run **`aio app deploy`** instead to compile frontend assets in clean cloud environment. |
| **Actions return 401 Unauthorized** | Session expired or not run in shell | Make sure you access the application using the **Experience Cloud Shell URL** (`https://experience.adobe.com/...`) generated during deploy. Do not access the raw CDN URL directly, as it requires IMS authentication headers. |
| **Event orchestrator does not fire** | Webhook configuration mismatch | Verify that Phase 7 event registration is complete and status is listed as **Active** in the developer console. |
| **AEP API calls return 403 Forbidden** | Client ID/Secret product profiles missing | Verify in the Adobe Admin Console that the Developer Workspace Integration has been assigned to a Product Profile with permissions to call Query Service, Sandboxes, and Flow Service. |
| **State is not saved / loaded** | AIO State init issues | Run `aio app list actions` to verify all 6 actions are deployed correctly. |
